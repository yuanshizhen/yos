# YOS 一体化数字平台 PRD（阶段规划 + 开发约束）

## 1. 项目背景
YOS 目标是构建「企业管理 + 家庭数字化 + 系统监控」的统一平台，采用现代化前后端分层架构，支持未来多团队并行开发、模块化扩展和容器化交付。

## 2. 总体目标
- 技术栈：前端（Vite + React + pnpm + TailwindCSS + Headless UI）与后端（Go）。
- 部署方式：前后端独立镜像，`docker compose` 一键构建与启动。
- 运行环境：Windows11 + Docker Desktop，依赖本机已有镜像（timescaledb、nginx、node、minio、redis）。
- 视觉规范：苹果风格（玻璃拟态、平滑动效、细腻层次、响应式适配 PC/Mobile）。

## 3. 用户角色
- 系统管理员：配置组织、模块、权限。
- 企业用户：访问仓储、财务、销售、计划、生产、人事、OA。
- 家庭用户：访问相册、记账、事件、资产。

## 4. 信息架构（一级导航）
- 主页
- 企业管理（仓储、财务、销售、计划、生产、人事、OA）
- 家庭数字化（相册、记账、事件、资产）
- 系统监控
- 设置

> 当前阶段用占位路由承载子模块，保证后续可渐进替换。

## 5. 非功能性要求
- 响应式：移动端优先，兼容桌面端。
- 可扩展：后端应用服务与基础设施解耦。
- 安全性：鉴权 token、上传类型/大小限制、环境变量注入。
- 可运维：健康检查、容器化、统一日志。

## 6. 技术架构
### 6.1 前端
- 架构：路由驱动 + 可复用 Apple UI 组件库。
- 组件层：`AppleButton`、`AppleCard`、`LoginModal`。
- 页面层：`HomePage` + 多业务占位页。
- 能力层：`services/api.ts` 统一 API 客户端。

### 6.2 后端
- 架构：轻量 Clean Architecture（domain/application/interfaces/infrastructure）。
- 认证：`/api/v1/auth/login` 返回 JWT。
- 头像上传：`/api/v1/upload/avatar`，通过对象存储适配层写入 MinIO，返回可访问 URL。

### 6.3 基础设施
- `docker-compose` 统一编排：frontend/backend/timescaledb/redis/minio。
- 对第三方镜像设置 `pull_policy: never`，避免额外拉取。

## 7. 第一阶段范围（本次交付）
### In Scope
1. 主页弹窗登录（非独立登录页）。
2. 登录成功后可上传头像并显示当前用户信息（内置超级管理员默认登录凭据自动填充）。
3. Apple 风格 UI 基础组件库。
4. 顶部导航 + 全局滚动条重设计。
5. 一键容器部署文档与脚本。

### Out of Scope
- 企业子系统业务逻辑。
- 家庭子系统业务逻辑。
- 复杂 RBAC 与多租户。

## 8. 验收标准（第一阶段）
- 启动后可访问主页；顶部导航可路由切换。
- 点击登录弹出对话框，输入用户名/密码可完成登录。
- 选择图片后可上传到对象存储并在主页展示头像。
- 移动端与桌面端均能正常布局。

## 9. 开发约束
- 前后端代码必须位于同一仓库的两个子目录：`frontend/` 与 `backend/`。
- 前后端必须可分别构建镜像并在 compose 中编排。
- 新增业务模块必须以独立路由 + 独立应用服务扩展，禁止跨层耦合。
- 所有运行参数通过环境变量注入，禁止硬编码生产密钥。

## 10. 分步骤实施计划
1. **Step A（已完成）**：搭建 monorepo 目录、compose、Makefile、容器镜像定义。
2. **Step B（已完成）**：前端 Apple 风格布局、导航、占位路由、登录弹窗、滚动条风格。
3. **Step C（已完成）**：后端登录与头像上传 API、MinIO 对象存储集成。
4. **Step D（下一步）**：接入 TimescaleDB/Redis 真实业务模型。
5. **Step E（下一步）**：权限体系、审计日志、监控告警。

## 11. 风险与缓解
- 风险：用户本机镜像缺失导致 compose 启动失败。
  - 缓解：README 明确先 `docker images` 自检。
- 风险：MinIO Bucket 初始化失败导致上传不可用。
  - 缓解：服务启动时自动建桶并在失败时快速报错。

- M2：完成企业管理核心 2 个模块 MVP。
